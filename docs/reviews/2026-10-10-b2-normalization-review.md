# B2 原件回查与字段候选复审

本轮只处理 B2 的 335 条新增候选，不更改 70 条历史记录、相机 FAE 运行时或活动知识指针。四组在受限原件中重新核对文件哈希与精确页/行；私有处置文件、337 条字段候选和复审包均保存在 Git 忽略目录 `data/knowledge/curated/b2-normalize-20261010/`。原文、摘录及审核 CSV 不进入 Git。

| 去向 | 原候选条数 |
| --- | ---: |
| 可拆分为有条件的字段候选 | 171 |
| 重复于同范围且同定位的候选 | 69 |
| 保留为选型、风险、排障上下文 | 47 |
| 复合表述仍需逐项核对 | 26 |
| 原件冲突 | 15 |
| 转录语气/内容与原件不符 | 3 |
| 暂无安全归一化解释 | 4 |
| **合计** | **335** |

171 条可拆分项和两条复合项的安全子事实共形成 337 条**未签认候选**。另有 8 条原有流程记录保持原 ID 与内容，不另造流程。没有新增 `verified`、权限或生产配置。最易误答的边界仍被保留：EGO 1600/1920 与泛称双目 EGO 不互相继承；EGO Pro 的试录建议不能改写为强制步骤；EG-DB 的相机数、RGB 帧率、蓝牙与麦克风冲突不能任选一值；UMI 抓力“3kg”的单位未裁决；HUB 单口 **最大** 5V/2A、四口合计 5V/3A、`<1μs` 通道偏差与 `<1ms` 同步不能合并；组合流程及 Wi-Fi 出流时序仍有缺口。

新增的候选归并器逐项比对原记录指纹、来源定位、产品/变体/组合范围与候选状态。旧抽取快照以章节段落为 Markdown 行范围，10 个候选引用的是其内部精确行；本轮仅为私有复审重读原件并生成 10 个有父片段约束的行定位，不改旧抽取快照或发布版本。337 条新候选通过 `validate_records`，发现数为 0；这只证明结构与引用可复现。

`review-delta-v6/` 包含 337 项 D2 事实/权限复审包、空白签认 CSV、来源→原候选→章节→新候选绑定、字段字典差异清单，以及输入/输出哈希摘要。构建器独立重读全部 98 个原候选定位（含无正向字段的条目），并核对绑定与原记录、章节范围、来源及断言。337 条候选涉及 149 个字段，其中 142 个尚无 B1 字典定义；5 个字段存在候选单位写法/类型不一致，2 个字段与旧字典的单位或比较符不符。旧字典中被复用的 7 个字段也仍处于候选状态。离线构建器没有可信的字段定义签认导入，因此全部 337 个复审项保持字段裁决阻断，不能仅凭字典里的状态字符串解除；每项审核指纹绑定对应字段的字典内容，字典改变须重新出包。全部文件为 `0600`、目录为 `0700`；CSV 导入校验的 337 项均为未签认。旧 572 项 D2 包仍是历史候选复审包；新的字段候选必须按精确新指纹重新审核，不能沿用旧签名。对高频更新，每次用新的输出目录构建，来源、字段、条件、权限发生变化即产生新的审核指纹，旧目录保留作审计。

**仍未完成的门：** 114 个原候选章节仍有 293 项正文/元数据一致性发现；48 条冲突、复合、原文不符或未决原候选需要内容裁决；142 个待补字段定义和旧字段差异、章节正文与角色应依审核结果重建。D1 独立受控原件归档及重取、苍渊的具名事实/权限签认、D3 真实 Dev 发布和 D4 Dev 回放及独立答案复审均未完成。当前活动知识仍是 `empty-dev-v0`，本轮候选不得提供在线正向答案。

复现工具为 `python -m scripts.prepare_b2_normalization_review`，需显式传入原候选、四组处置文件、原抽取快照、受限原件根目录、章节绑定、章节索引、B1 字典及新输出目录。它拒绝覆盖已有复审包；输出摘要记录每项输入的 SHA-256 与新候选/审核包的 SHA-256。
