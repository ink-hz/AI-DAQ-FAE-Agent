# DAQ FAE 知识库质量提升任务书

**日期：** 2026-10-21
**执行依据：** [知识库设计与持续更新工作流](knowledge-base-design-and-update-workflow.md)。
**任务性质：** 面向后续开发会话的实施任务；本文不代表事实签认、知识激活或生产部署。

## 1. 目标、起点与完成定义

本轮只提升 DAQ 知识库的来源覆盖、PDF/Markdown 清洗、事实与章节一致性、已审章节发布和后续增量更新能力。问题生成与回答表现可作为后续 Dev 验证，不能代替知识层验收；不修改相机 FAE 知识和发布指针。

| 截至本文编写时可核实的起点 | 含义 |
| --- | --- |
| 产品归档 276 件：14 PDF、6 Markdown、7 TXT、249 资产 | 27 件可提取文本都已进入 A1 来源处置，但处置不等于事实审核。 |
| A2/A3/A4 共 114 个产品、系统、指导候选章节 | 私有候选有正文和来源；审核、权限、运行时发布不能由文件存在推定。 |
| B3 候选图 742 条记录、712 个覆盖单元 | 离线归一化与影响分析资产，不是 742 条已审事实。 |
| 2026-10-20 文档记录的主知识发布为 65 条记录、0 个章节 | 其中 55 条规格 claim；仅引用 10 份唯一产品原件。执行前须重新读取**实际目标环境**的活动身份。 |
| C3 软件证据矩阵 36 行，状态为候选 | 包存在、文档声明和设备/组合实测不得混同。 |

以上数量的来源分别见 `data/knowledge/curated/a1-20261010/`、`a2-20261010/`、`a3-20261010/`、`a4-20261010/`、`b3-normalized-20261012/`、`c3-20261010/` 与[增量发布记录](../reviews/2026-10-20-daq-quality-improvement/spec-extension-release-20261020.md)。私有目录 Git 忽略，仓库文档只记脱敏聚合及清单哈希。

**本轮完成**必须同时满足：重点原件到章节/字段的双向覆盖可复算；八个产品的身份、规格和缺口有稳定矩阵；至少一个真实产品章节和一个真实系统流程章节通过新的叙述核对合同进入独立 Dev 发布并由工具按角色取到；其余候选逐项标明“已审可发布、待事实/权限审核、冲突、缺原件”及原因；一次模拟资料更新能给出精确影响、撤回和回滚记录。首批章节数量是打通机制的最低门，不表示全部 114 节可发布。生产切换另按既有发布程序执行。

## 2. 执行边界和交接规则

- 只在 DAQ 仓及其受控私有候选/原件目录开展本任务；不把受限 PDF、章节正文、审核账本提交到 Git。
- 现有已审 65 条记录保持不可变。需要修正时生成新批次和新发布，不原位改历史清单。
- 不因“方便回答”批量放开冲突、推断 SDK 兼容、从单机外推组合，或用模型自评替代来源审核。
- 每个任务结束留下输入清单/代码身份、产物哈希、审核状态、未通过项和下一任务依赖。未拿到事实或权限审核时，工程任务仍可完成私有候选与静态检查，但不得称发布完成。
- 每次执行先检查 `git status` 和实际分支身份，只提交本任务文件；是否存在其他会话改动以现场检查为准，不清理或覆盖其他改动。
- 任务的“通过”只针对明确交付物；源资料缺失时交付有边界的缺口结论，不能补写没有来源的正面事实。

## 3. 交付文件及责任边界

| 产物 | 建议位置 | 责任 |
| --- | --- | --- |

| 发布包与活动指针 | 现有受控 `data/knowledge/published` 及目标环境对应存储 | 发布者使用现有不可变发布与显式激活机制；Dev 与生产身份分开。 |

事实审核者核对产品/变体/字段/条件/流程，权限审核者核对查看和转发角色；发布者不得替代任一审核。相机模块只读投影还需相机事实维护者确认固定版本及 EG-DB 装配关系。责任角色可由现有项目授权人员兼任，但每项决定单独留痕。

## 4. 工作包

### KQ-00｜冻结执行基线与范围（P0，无前置）

**工作：** 读取执行目标环境的活动主知识（含已审 link 记录）、SDK、运行时代码和角色身份；逐项与本机候选/发布记录区分。冻结 8 个产品实体：EGO 1600、EGO 1920、EGO Pro、EG-DB、WristCam、UMI Finger、UMI 视觉模块、HUB。系统范围包括 EGO 单机、EGO Pro 单机、EGO＋双 WristCam＋HUB、EGO USB PC 和 Wi-Fi PC，具体适用变体仍按原件裁决。列出本轮优先问题类型，不把问题文本当知识来源。

**交付：** 基线身份表、实体/系统清单、现有活动记录与章节计数、保留的旧发布 ID。
**验收：** 可重复加载同一活动 ID；本机旧 `active.json` 与生产发布记录若不同，差异明列而不择一冒称线上状态。

### KQ-01｜原件到章节/字段的双向覆盖账本（P0，依赖 KQ-00）

**工作：** 在 A1 27 件文本处置与 249 件资产目录上增加“原件页/表/段 → 候选章节/字段/流程 → 已审发布或明确缺口”的映射。先覆盖全部 14 份 PDF、6 份 MD、7 份 TXT 的文档级处置；对本轮重点实体逐页/逐表核对技术内容。资产按技术候选、冲突/版本疑点、索引用途、重复和敏感需脱敏分类，先处理与本轮字段/流程相关的图片，其他资产保留明确处置而非虚报可答。

**复用：** `source_import.py`、`source_disposition.py`、`scripts/audit_daq_material_coverage.py`、A1/A2 私有审计。
**交付：** 私有来源覆盖账本与脱敏摘要，标识每条未进入发布的原因和责任角色。
**验收：** 27/27 文本、249/249 资产有唯一处置；同名异版和同字节副本分开；从重点发布事实能反查原件，从重点原件页/表能正查章节、字段或缺口；无原件路径泄漏到答案正文。

### KQ-02｜PDF 表格和 Markdown 深度清洗（P0，依赖 KQ-01）

**工作：** 以现有 A2 产品章节为底稿，对八个产品核对身份、规格表、单位/比较符、脚注、版本、适用条件、软件声明及资料冲突；分别审核 A3 系统步骤的前提、检查点和失败分支，A4 选型/风险候选的证据层级。优先处理 EG-DB、EGO 两变体、HUB 的规格表及 EGO 单机、EGO＋双 WristCam＋HUB 的流程。必要时对表格页做目视复核；OCR、图像或合并单元格输出不自动成为事实。将候选正文中的“候选/审核状态”移到元数据，已审正文只保留用户有用的知识与边界。

**交付：** 新的私有、不可变候选批次；逐页/逐表差异、冲突和缺项；每节稳定 `section_id`、来源定位与内容哈希。
**验收：** 每个产品有入口及明确缺口；重点表格的数值、单位、比较符和条件与原件一致；不同变体不混写；流程步骤不能由单机/组件证据外推。改变来源或正文时旧审核标为失效，不修改 A2/A3/A4 历史底稿。

### KQ-03｜统一字段字典、事实矩阵和缺口矩阵（P0，依赖 KQ-01/KQ-02）

**工作：** 以现有 55 条已审 claim 为种子，建立实体×字段×条件的覆盖单元；比对所有重点规格表，补出“文档有而记录没有”的候选、冲突或缺证。为字段定义对象、单位、比较符和可接受同义词。流程、拓扑及软件关系另建覆盖维度；C3 的 36 行仍按包存在、文档声明、源码、单机实测、组合实测分层，不把候选直接升级。

**复用：** `records.py`、`normalization_review.py`、`identity_coverage.py`、B3 候选图、C3 软件矩阵。
**交付：** 私有字段/关系矩阵、候选记录、冲突决议清单和脱敏覆盖摘要。
**验收：** 每个已审字段有唯一明确的实体和条件范围；每个重点原件参数落在已发布、候选、冲突、已审计无来源或未审计之一；`unknown`、`unsupported` 和冲突分开；新增候选不改变现有活动发布。

### KQ-04｜叙述章节与类型化事实一致性合同（P0，依赖 KQ-02/KQ-03）

**阻断点：** 现有[章节发布 v2](../knowledge/section-release-v2.md)和[B2 一致性 v1](../knowledge/section-record-consistency-v1.md)只认可精确类型化断言块；自由叙述是 `uncovered_body`。因此本任务是发布真实章节的前置，不允许只改 `review_status` 绕过。

**工作：** 设计并实现逐段/逐表行/逐步骤的证据单元：稳定 ID、精确正文片段哈希、来源、实体/拓扑、条件、记录依赖、知识类型及审核状态。检查全文实质断言均被证据单元覆盖；数值断言与 claim 完全一致，流程要素与 procedure/topology 一致；纯解释性摘要需要逐段来源和具名事实复审。变化传播到章节审核指纹和影响图。为混合权限或适用范围的章节提供拆分规则。

**建议修改点：** `daq_fae/knowledge/section_consistency.py`、`section_release.py`、`candidate_sections.py`、`content_review_queue.py`、`update_impact.py` 及对应单元/合同测试；尽量扩展现有 v2 合同，不建立平行发布器。
**交付：** 可复算的新叙述核对合同、实现、正反样例和迁移说明。
**验收：** 一个真实产品章和一个真实系统流程章在私有预览中通过完整覆盖；漏映射段落、冲突数值、删条件、错页码、旧审核指纹、混合角色均拒绝；单纯调整排版不应悄悄改变事实审核语义。

### KQ-05｜事实与权限双审核，分批生成可发布知识（P0，依赖 KQ-03/KQ-04）

**工作：** 将首批安全章节及新增事实做逐项来源复核与角色复核；一个章节的每个证据单元、依赖记录、正文和权限均绑定审核指纹。先处理 KQ-02 的重点产品和系统，再处理其余八产品和 A3/A4 候选；无法裁决的章节保留候选，必要时拆成可发布与阻断两节。SDK 继续用独立审核与发布合同；link 是主知识内的专门记录，仍须独立链接核验和转发权限审核，不能随普通章节顺带授予权限。

**交付：** 具名事实审核、具名权限审核、可发布/待审/冲突/缺原件章节清单。
**验收：** 至少一个真实产品章和一个真实系统流程章具备完整审核；所有拟发布记录和章节的来源哈希、定位、适用条件、角色一致；未获审核的 A2/A3/A4 段落在运行时不可见。审核人名和日期是审计信息，不以脚本自动填充代替决定。

### KQ-06｜不可变 Dev 发布与工具消费闭环（P0，依赖 KQ-05）

**工作：** 用现有发布器构建包含已审记录和已审章节的主知识新版本；先在隔离根完成发布前静态与加载合同验证，再显式激活到独立 Dev，并用实际 `ReviewedKnowledge.load_active` 读取活动版本。按 `internal_fae` 及其他已授权角色检查 `lookup_spec`、`search_knowledge`、`read_doc`、流程工具和缺口状态。记录主知识与 SDK 发布的绑定及主知识内 link 记录数量，验证旧版可回滚。原有 65 条若无撤回原因须保持可见；新增章节不改变相机服务。

**复用：** `releases.py`、`reviewed_view.py`、`release_readiness.py`、`domain_tools.py`、[现有发布合同](../knowledge/section-release-v2.md)。

**执行补充（2026-10-21）：** 现有 owner v1～v4 记录发布器均拒绝非空章节，v3 运行时重绑定还要求成组镜像切换，不能改空数组限制来绕过。首批章节沿现有 v2/D3 公共发布器走显式 `allow_local_dev=True` 的本机路径：核验原有本机原件、保留独立事实/权限决定与内容绑定审核适配器，不恢复已由负责人移除的独立持久复制和具名 D2 签名要求。默认加载器和认证应用不接受该本机模式；它只完成隔离 Dev 的知识/工具验收。生产需要另建符合其现行合同的候选，并同步绑定运行时和 SDK。发布器须保留受审字段别名、变体解析及操作场景保护，不能因换发布信封而丢失。
**交付：** Dev 发布 ID、清单摘要、角色可见记录/章节数、工具取证记录及回滚身份。
**验收：** Dev `section_count > 0` 且包含 KQ-05 的两个真实章节；事实与章节均能按实体/条件召回；无权限角色在检索、精读及结构化来源中均看不到受限内容；加载或审核失败时活动指针不变。生产切换不计入本任务自动完成。

### KQ-07｜资料增量更新与撤回演练（P1，依赖 KQ-01/KQ-03/KQ-04/KQ-06）

**工作：** 按[更新影响合同](../contracts/knowledge-update-impact-v1.md)演练一份规格书字节变化、一处表值变化、一份来源删除、一项权限扩大/收缩以及新增来源改变原有“无资料”判断。只重审影响闭包，但不能遗漏章节、负面覆盖和 SDK/链接关系。保留历史版本，演练回滚。

**交付：** 旧新输入哈希、影响图、撤回/可复用审核清单、新版候选和回滚记录。
**验收：** 被删除来源支撑的正向证据撤回；新资料触发相关缺口复查；旧审核不因内容/条件/角色改变被复用；无关实体不被误改；失败构建不改变活动指针。

### KQ-08｜知识层验收与维护交接（P1，依赖 KQ-06/KQ-07）

**工作：** 按本任务书逐项复算来源、清洗、矩阵、审核、发布和工具可见性；把每个未发布候选写成明确的剩余任务与阻断证据。形成一次新增资料的最小示例及操作记录，让后来维护者不依赖本次会话。Dev 问答语义复审可随后按既有质量门执行，但本任务不把旧测试报告当知识覆盖证明。

**交付：** 脱敏验收报告、私有可复算索引、维护示例、剩余缺口表。
**验收：** 任抽一个已发布事实、已发布章节、冲突项、仅候选项和资产项，都能在“原件→候选→审核→发布→工具”链上解释其状态；文档中的命令和路径在当前仓库仍有效；他人可按工作流完成一次更新而不手改发布清单。

## 5. 顺序、停点与检查表

```text
KQ-00 → KQ-01 → KQ-02 → KQ-03 → KQ-04 → KQ-05 → KQ-06 → KQ-07 → KQ-08
                  └──────────── KQ-03 可与不冲突的章节清洗交错进行
```

KQ-01～KQ-04 的工程与候选工作不等待具名事实审核；KQ-05 没有审核决定时停止发布受影响内容，继续处理独立的已审范围。每个工作包结束后记录“未开始 / 私有候选完成 / 审核完成 / Dev 发布完成 / 生产发布完成”之一；不得用单一“完成”掩盖层级。生产发布需要另走现有审批、构建和回滚程序。

最终复核表：

- [ ] 27 件文本及 249 件资产处置可复算，重点表格有页/行和视觉复核记录。
- [ ] 八个实体和五个系统的覆盖矩阵区分已发布、候选、冲突和缺口。
- [ ] 所有新增硬参数的值、单位、比较符、条件及版本与来源一致。
- [ ] 叙述章节没有 `uncovered_body` 的实质断言，也没有绕过 B2 的审核快捷路径。
- [ ] 至少一个真实产品章和一个真实系统流程章进入 Dev 活动发布并可按角色精读。
- [ ] 原有 65 条记录的保留或撤回逐条有依据；SDK/链接没有被主知识发布自动升格。
- [ ] 模拟新增、变化、删除和权限变化时，影响与撤回清单正确，回滚身份明确。
- [ ] 相机 FAE 的源码、知识、索引和发布指针未因 DAQ 知识更新改变。

## 6. 每项交接记录格式

每个工作包的记录至少写：`任务 ID / 执行代码 SHA / 输入归档与活动知识 ID / 私有产物哈希 / 变更的实体、字段、章节 ID / 原件复核方式 / 事实审核决定 / 权限审核决定 / 静态与 Dev 结果 / 未关闭问题 / 下一依赖 / 回滚目标`。没有适用的审核决定写“未审核，保持候选”，不留空白让后续误认通过。

这份任务书是知识库专项；请求理解、上下文管理、Prompt 和回答合成的改进按既有质量任务书处理。若知识层完成后仍出现“已发布且工具可见，但答案短或未用证据”，应沿工具结果、需求覆盖和合成链另行定位，不能继续扩充原件库存来代替排查。
