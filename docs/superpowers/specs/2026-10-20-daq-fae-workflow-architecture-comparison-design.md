# DAQ FAE 与相机 FAE 工作流、架构及知识体系对比分析设计

**日期**：2026-10-20

**状态**：分析设计；尚未形成当前生产根因结论

**目标**：以已经较成熟的相机 FAE 为工程基线，从数采 FAE 应完成的技术支持任务出发，查明回答简短、弃答、漏答背后的工作流和系统原因，并区分移植缺陷、DAQ 领域设计不足、知识发布不足及运行环境差异。

## 1. 已知基线与分析原则

- 两仓当前提交的共享 `src` Git 树相同（`e69021117158cbdc7e6d75220c5247fe631bbe58`）。DAQ 的入口、请求 schema、会话状态、领域工具、证据策略和知识发布代码主要位于 `daq_fae/`；知识快照与 SDK 资料由 `data/knowledge/`、`Knowledge_SDK/` 管理，提示词位于 `prompts/`。共享底座相同不代表系统能力相同。
- 相机 FAE 作为成熟工程基线时，以其实际发布身份及对应的已验证实现为准；当前工作树、未提交文档和 DAQ 锁定的上游源码版本都不能自动代表相机生产版本。
- [2026-10-20 DAQ 发布记录](../../reviews/2026-10-20-daq-scenario-production-release.md)绑定代码 `7d7232902cdd6cdea2baf4d61ccc0960ef1ab428`、运行时 `daq-ba50906bd98b`、27 条主知识、24 条 SDK 用法和 17 条日志。最终代码身份下 55 道核心题未整套重跑，多轮完成 9/13 组。既有聚焦 Dev 结果不足以证明整体工作流达到相机 FAE 水平。
- [2026-10-12 工作流审计](../../reviews/2026-10-12-daq-workflow-architecture-audit.md)曾发现请求目标、账本、泛检索和会话/trace 接口错位。该审计早于多轮架构修改；其结论只作为待复核风险，不直接标为当前缺陷。
- [2026-10-18 独立复审](../../reviews/2026-10-18-daq-current-release-codex-review.md)记录过有据却漏答、目标范围混合和硬条件推荐错误。这些旧身份失败可作为追踪样本，不能直接外推到最新生产。
- 少量 2026-10-20 Dev 答案有数百字，部分超过 800 字。因此“生产回答很简短”不能先归因于统一的字数限制；需要沿系统链路核实。
- 这些发布记录只证明记录当时的身份。开始分析时必须重新核对可访问的当前运行身份；若没有线上只读访问，就将结论限定为仓库版本与已存回放，不能称其为当前生产现状。

比较的对象是**相机成熟工作流中的能力契约，以及 DAQ 是否具备并兑现这些能力**，不是类名、文件数量、提示词长度或两个产品域的知识总量。相机的工作流设计和已验证实现是工程基线；DAQ 不必复制相机专用 `Orchestrator` 或知识目录，但应能解释每项能力如何在自己的领域实现。

### 设计自审与纠偏

上一版仍有四个偏差，修订后的调查须主动避免：

1. **对标相机过于抽象**：只说“工作流相似”无法发现移植遗漏。逐项列出相机已验证的上下文、schema、能力取证、覆盖、合成、outcome 和质量门，给出 DAQ 对应入口、接口、数据及验证证据；没有对应物就是待查缺口。
2. **先铺开全仓审计，后找运行证据**：这容易得到庞大的差异清单，却无法解释质量体验。先选少量高价值纵向样本并冻结版本，再沿样本涉及的架构路径展开；共性问题出现后才扩大覆盖。
3. **把“不同”直接当“倒退”**：数采知识尚未发布、角色不可见、模型/网关配置差异和代码移植错误会产生相同症状。每个结论必须有时间线、对照或可证伪探针，标明是历史已修、当前仍在、从未具备还是无法判断。
4. **缺少停止标准**：不能无限增加题目或只交“建议继续测试”。优先问题须定位到有证据的层与机制，或明确列出阻断定位的缺失数据；其余风险单列，不能冒充已证实根因。

## 2. 分析路线选择

| 路线 | 作用 | 局限 |
| --- | --- | --- |
| 只比代码与配置 | 找移植差异、版本漂移和明显缺口 | 代码存在不等于线上被调用，也不证明答案受影响 |
| 只比用户看到的答案 | 量化主观质量差距 | 无法区分知识缺失、上下文错误、证据误拦与展示问题 |
| **症状锚点与任务契约 → 纵向追踪 → 架构/知识横向对照** | 同时定位具体失效机制和可泛化的系统缺口 | 需要冻结版本、逐层读取证据，并承认缺 trace 时的未知项 |

采用第三条。先用现有问题和 trace 确定几条纵向路径，同时做不依赖新模型调用的契约/知识探针；必要时才用隔离 Dev 回放验证单一假设。随后把已证实的局部缺口扩展到同类任务，而不是先做全仓差异清单。

## 3. 对照框架：每层比较什么

以相机仓的 [工作流地图](../../../../AI-FAE-Agent/AI_FAE_Agent_工作流设计.md) 和已验证实现建立工程基线，再用 DAQ 的 [完整设计](../../2026-10-08-数采FAE完整设计.md)与当前实现逐项映射。每层记录：相机基线能力及验证、DAQ 对应设计与代码、实际入口是否调用、输入输出契约、运行证据和用户影响。文档声明与代码运行结果冲突时，以冻结版本的运行证据为准。数采产品事实、组合和软件支持仍须由数采受治理来源独立证明。

| 层 | 核心不变量 | 主要核对对象 |
| --- | --- | --- |
| 入口与身份 | Web、Task、Dev 的身份、角色、资料权限和错误语义一致；入口差异不改变领域判断 | 路由、角色映射、三个入口的装配与请求 trace |
| 上下文管理 | 已确认设备、变体、组合、平台、版本、已试步骤及未解决目标有来源和生命周期；追问继承、切题清空 | 相机会话状态与 DAQ `durable_state.py`、`task_context.py`、读写 checkpoint |
| 请求理解与实体接地 | 原问转成可审计的子目标、实体、条件、软硬约束和附件依赖；用户断言不升格为产品事实 | 两仓 schema、实体解析、有效问句、低信心处理 |
| 能力编排 | 多目标问题能调用多种能力；工具选择与“目标怎样算已证实”分离 | Loop 接口、允许工具集、任务计划与执行 trace |
| 知识生产与发布 | 原件经过来源核验、结构化、冲突裁决、角色审查和不可变发布后才可答 | 两仓来源清单、facts/SDK/links 与 DAQ release、候选/发布差异 |
| 检索与证据工具 | 有据事实按实体、变体、版本、条件和角色可召回；`not_found`、冲突、错误语义明确 | 索引、记录/章节路由、工具参数、返回 ID/状态/来源 |
| 覆盖与终稿 | 已取证据正确匹配子目标；已知部分可以交付，未知部分不冒充已证实 | 需求账本、EvidencePolicy、`submit_answer` 字段、渲染器 |
| 提示词与控制边界 | 领域指导、工具契约和确定性门各守其职；局部规则不会吞掉可回答内容 | 系统/Schema 提示、工具说明、归一器、终稿协议和证据策略 |
| 结果与可观测性 | outcome、fallback、sources、阶段、历史与前端所见一致；能追到最早失效层 | trace、SSE、持久化、UI、反馈与评测记录 |
| 配置与发布身份 | 模型、网关协议、预算、提示词和知识版本与运行身份一致；差异可追踪 | 构建清单、实际 health、模型回显、Provider 错误与提示版本 |

每层先判断**是否有能力**，再判断**是否接入相关入口**，最后判断**是否在代表性问题中生效**。不同入口不必输出相同答案，但相同权限、知识身份和用户目标下的实体、条件、证据与终态规则须一致。过去审计提出的缺口逐项重新验现状；已修复项和仍存问题分开记。

第一轮映射以这些源码为锚，表中 DAQ 路径仅表示**候选对应物**，不预先判定功能等价：

| 相机成熟能力及入口 | DAQ 候选对应物 | 必须拿到的等价证据 |
| --- | --- | --- |
| `src/agent/session.py`、`orchestrator.py` 的会话接地、有效问句和切题 | `daq_fae/durable_state.py`、`task_context.py`、`workflow.py` | 同一追问链的 checkpoint 写入、读取、继承和失效记录 |
| `schema_extractor.py` 与 `orchestrator.py` 的目标/条件校验 | `daq_fae/request_schema.py`、`workflow.py` | 多子目标、变体、软硬条件进入 Loop 前后保持一致 |
| `src/agent/loop/` 与按能力取证的工具 | 共享 Loop 加 `daq_fae/domain_tools.py` | 已发布事实在正确工具及条件下可达，工具错误不伪装缺证 |
| 相机事实、SDK、链接的分层知识与证据门 | `daq_fae/knowledge/`、`Knowledge_SDK/`、`domain_evidence.py` | 来源身份、角色、范围、冲突和目标覆盖在发布→检索→终稿中不丢失 |
| `evals/run_eval.py`、失败哨兵和独立质量复审 | DAQ 回放脚本、题集、复审记录 | 当前代码/知识身份下覆盖对应任务类型，保留原始失败与四轴判断 |

## 4. 两项重点深查

### 4.1 知识库质量与可回答范围

“文件已经归档”“进入候选图”“已审发布”“当前角色能检到”“足以回答此问题”是五个不同状态。按产品实体、变体、规格字段、测量条件、组合拓扑、操作流程、软件/固件兼容、SDK 用法、排障经验、官方链接建立覆盖矩阵；每个 cell 记录原件、候选、发布、角色、检索结果及冲突/过期状态。覆盖的分母来自实际高频任务及相机工作流所要求的能力类型，不用文件数或记录数充当问题覆盖率。

重点检查：

1. **来源与身份**：SKU/修订、别名、模块和整机、单机和组合是否被错误合并；来源哈希、页/章节、版本及适用条件是否可回溯。
2. **事实表达**：数值、单位、测量条件和 qualifier 是否完整；“明确不支持”“未取得证据”“来源冲突”是否分别建模。
3. **发布覆盖**：按[原件覆盖审计](../../reviews/2026-10-16-daq-full-material-coverage.md)复算归档→候选→可答的损耗，优先看高频问题的关键事实，不用记录总数代替实际覆盖。
4. **检索兑现**：对每个已发布正例做无模型工具探针，记录工具入口、参数、命中、来源和 requirement ID；候选章节的相关性不能直接证明规格或兼容。
5. **更新与治理**：资料变更如何发现、裁决、重签、发布、回滚；同一问题在不同 release 是否因知识身份变化而得到不同答案。

每个任务再评估六项质量：来源可信与可追溯、实体/条件表达准确、当前版本和角色适用、冲突处理、工具可召回、能否支撑专业且可执行的回答。分别报告“有权威资料但尚未发布”“已发布但检索失败”“已检出但证据不充分”；知识矩阵独立报告，不把“没有发布证据”计成推理失败，也不把“已发布但没检出”计成资料缺失。

### 4.2 上下文与多轮状态

分别追踪单轮输入、前置 schema、Loop 输入、持久 checkpoint、下一轮读取和最终答案。检查设备/变体切换、单机↔组合、SDK 包内用法↔设备支持、历史比较版本↔当前设备版本、附件重读和用户纠正。每个字段必须标明 `user_supplied / source_verified / inferred / unknown`，记录创建者、轮次、读取点、覆盖规则和失效条件；反例包括用户否认旧条件、切换产品及历史版本只用于比较。

浏览器认证与本机 Dev 可在同权限、同知识版本下比较领域状态。Platform Task 有不同的上下文与生命周期，按共享不变量比较目标、证据和权限边界，不要求逐字或逐状态相同。Task 摘录仍是未核实提示，不能变成用户断言或系统事实。若 trace 缺少有效问句或状态转移，记为观测缺口，不仅看最终是否碰巧答对。

## 5. 从架构缺口到用户症状的验证

```text
设计契约与发布身份
  → 入口/上下文/请求目标
  → 能力与工具查询
  → 知识返回及适用范围
  → 需求状态和终稿字段
  → 后端答案/SSE/历史/前端展示
```

每个样本记录相邻层的输入、输出和第一次丢失的用户目标或受审事实。把“答不出来”固定分成：当前无权威资料、资料有但未发布、已发布但未检出、检出但目标未获覆盖、覆盖已满足但合成漏写、Provider/运行失败、展示不完整。短答则核对用户明确子目标和本轮已取证据的兑现情况；字数仅作描述，不作为合格线。

样本分两层：

- **症状锚点**：优先选用户实际指出的短答、错误弃答、漏答和多轮失败，保留脱敏原问、上下文、时间、实际可见答案和 trace ID。先用可得样本定位，不把取得 20–30 条生产样本当作开展架构审计的前提。
- **同类能力对照**：两 Agent 各用本领域有已审证据的对应题型，覆盖单事实、条件规格、复合目标、选型、SDK、排障和多轮。相机不回答 DAQ 产品事实；独立复审比较目标保持、取证、边界、已知部分交付与工程可用性。两侧知识不对称单列，不混成“架构得分”。

答案独立复审沿用相机仓[四轴口径](../../../../AI-FAE-Agent/docs/architecture/评测四轴与运行时去补丁设计_20260714.md)：语义事实、运行硬门、协议一致性、展示质量分开。回答模型不自评。自动断言只作预检；结论须由 Codex 或人工 FAE 阅读问题、来源、完整答案与 trace。不能用 HTTP 200、`resolved`、来源数量或字数替代专业答案判断。

## 6. 执行顺序、归因和判停

1. **冻结身份与首批纵向样本**：核对相机实际基线和 DAQ 的代码、可读到的运行版本、模型/网关、提示、角色、知识发布及入口。先取已有材料中覆盖“短答”“有据弃答”“多轮丢条件”的少量样本；历史审计、旧版本结果和当前版本分开。
2. **逐题追到最早失效层**：对每题写用户目标、相机基线能力、DAQ 实际状态流和来源流。优先用已存 trace、发布清单和无模型探针验证；如果是当前行为且仍不明，再在隔离 Dev 做最小回放。每个推断必须附能推翻它的反例。
3. **从样本扩成架构矩阵**：按第 3 节核查同类入口和边界，判断该问题是单题措辞、某类任务通病还是独立发布知识缺口。对每个失效类选一个邻近正例、一个反例，防止把偶然输出当架构规律。
4. **对照相机成熟基线**：把相机已具备的机制、质量门和实际行为映射到 DAQ 对应物；分别报告“缺失”“接入错误”“数据不足”“功能等价”“尚无证据”。相机资料不替 DAQ 产品背书。
5. **独立复审与排序**：同类任务盲评只验证系统差异是否造成用户可感知的损失。按实际影响、可复现性、影响范围和修复责任排序。一个变量一次只做一项隔离 Dev 验证；不以重复回放次数换取偶然通过。

归因标签必须选其一或列出可分辨的并列机制：`migration_mismatch`（相机基线能力在 DAQ 移植时缺失/错接）、`daq_domain_design_gap`、`knowledge_source_gap`、`knowledge_publication_gap`、`retrieval_or_evidence_gap`、`context_state_gap`、`runtime_or_provider_gap`、`presentation_gap`、`shared_or_unrelated`、`unresolved`。同时标明时间属性：`historical_fixed / current_reproduced / never_implemented / version_unknown`。跨领域差异没有时间证据时只称“能力差距”，不称“质量倒退”。

每条优先发现达到以下任一状态即停止该条调查：**确认**（有冻结身份、可复现输入输出、最早失效层和反例）、**排除**（证据推翻原假设）、**未定位**（准确列出缺少的生产 trace、权限或资料以及已完成的检查）。已确认问题可以进入修复设计；未定位项不能用猜测填满。广度扩张只服务于确认影响范围，不要求机械跑完所有题集才产出阶段结论。

核心假设及判别方式：

| 假设 | 支持证据 | 推翻方式 |
| --- | --- | --- |
| 领域编排没有完整承接相机工作流 | 相机有已验证的对应能力，DAQ 的目标或有效问句进入 Loop 前已丢失 | DAQ 在相关入口保留目标、调用合适工具并正确交付 |
| 知识治理/发布是主瓶颈 | 高频问题原件有内容但未形成同身份、同条件、角色可见的已审记录 | 已发布记录完整且可由正确工具稳定检出 |
| 上下文管理造成多轮退化 | checkpoint 没有保存或错误继承当前变体、版本、组合与用户纠正 | 冻结多轮 trace 证明状态写入、读取、切换均正确 |
| 证据契约过严或映射错误 | 工具返回相关来源，账本仍缺失，终稿丢掉已知部分 | 需求状态与来源范围一致，丢失只发生在后续合成/展示 |
| 终稿/展示使答案显短 | `submit_answer`、后端答案、SSE、历史、UI 之间有内容损失，或有据单元在合成时被省略 | 各层文字一致且已回答全部有据目标；短是问题本身所需 |
| 模型、网关或发布配置改变行为 | 冻结的知识与目标相同，但实际模型、工具协议、预算或提示版本不同并与失效对应 | 配置与回显一致，差异在其之前的知识/状态/工具层可复现 |

## 7. 交付物与边界

产出一份**相机能力 → DAQ 对应物矩阵**、按真实任务加权的知识覆盖/质量矩阵、上下文状态流图、代表性问题的逐层证据链、同类任务独立复审及根因排序。每条发现记录：`finding_id`、问题与受影响任务、基线能力、DAQ 版本身份、首次偏离层、关键来源/trace、无模型或 Dev 复现、反例、归因标签、时间属性、置信度和下一步。分开呈现已确认、已排除与未定位项；不得将缺少生产样本隐藏在总体通过率里。

阶段交付判据是：首批三类症状各有可审计证据链或明确的观测阻断；架构矩阵中的关键能力都有相机锚点和 DAQ 对应证据/缺口；知识矩阵能区分来源、发布、检索与回答四处损耗；主要根因有独立反例验证。只有证据闭合后才设计对应修复与回归门，不在这份分析设计中预选“大改模型”“加提示词”或“全部导入资料”。

用户问题、附件、完整答案和内部 trace 如含敏感内容，放 Git 忽略的受限目录；跟踪文档只保留脱敏摘要和哈希。原件、候选章节与用户附件不自动成为权威知识。任何新模型回放、提示消融只在隔离 Dev；不对生产 `/chat` 做评测，也不把旧身份结果改写为新身份通过。
