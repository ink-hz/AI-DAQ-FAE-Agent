# DAQ K-3 软件与交付证据候选复审设计

K-3 在现有 K-1 已验证归档和 K-2 复审包之上准备软件证据。原包中的安装包、固件和 Viewer 文件只证明特定字节存在，不证明设备兼容、功能可用或允许交付。变更记录能给出按版本定位的候选主张，但未经设备测试与资料权限审核不得成为 `verified software`。

## 候选结构

复用 K-2 `review-packet` 的稳定议题 ID、来源哈希、缺口和更新差异。文本选择器仍返回 PDF 页或 Markdown/TXT 行定位；新增 `asset_path` 选择器以相对路径 glob 缩小范围、以文件名正则匹配归档内 `kind=asset` 的资产，返回文件 SHA、大小和 `{"kind":"file"}` 定位，并显式标为 `asset_metadata_only`。父目录名称不能单独令文件命中。资产内容不解包、不索引、不生成 URL。所有角色查看和转发权限继续为 `pending`。

K-3 配方覆盖平台和版本包清单、SDK/Viewer/固件变更记录、EGO/EGO Pro/WristCam 相关功能候选、占位或未核验链接、Gemini 335L 模块与 EG-DB 整机的证据边界。议题问题必须包含需要复审的设备修订、平台、连接方式、软件版本和能力条件；缺任何一项不能推断端到端支持。相机模块投影须等待固定版本和包含关系裁决，不复制当前相机知识到 DAQ 答案层。

## 发布边界

复审人分别确认事实、设备测试、来源/角色授权和链接逐页语义。包名或本地路径不能变成下载链接；`README.txt` 中的地址只保留为候选线索。正式 `software`、`link` 记录继续受 K-1 的 `fact_review`、`access_review` 和 `link_review` 指纹门约束。新资料到来时生成新归档和新包，用差异报告重审受影响议题；旧知识版本不原地改写。
