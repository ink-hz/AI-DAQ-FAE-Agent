# 数采知识增量导入与本地发布设计

## 范围

本批实现任务书 K-1 的离线候选导入、稳定证据 ID、受治理记录校验、差异审计、本地只读发布和回滚。它不将候选资料自动提升为已核验知识，不接入在线 Agent，也不宣称真实资料可供试点使用。原始包从经 SHA-256 清单核验的仓外归档读取；当前同机归档只支持 Dev 开发，持久受控存储仍是正式发布门。

## 决策

1. 每次资料更新先产生新的不可变原始归档。导入器验证独立记录的 manifest 哈希及逐文件哈希；按相对路径比较新增、变更、删除。相同输入生成相同候选快照，不靠文件修改时间判断新旧。
2. PDF 按页、Markdown 按标题及行、TXT 按行组生成候选文本。每个片段带文件路径、SHA-256、页或行定位和内容哈希。软件、固件、图片、视频、DOCX 等暂只生成元数据和待处理状态；它们不能进入文本检索。空白 PDF 页记录为待 OCR，不补编内容。
3. 产品、规格主张、组合拓扑、操作流程、软件关系和交付入口分别有稳定记录 ID。事实审核和资料权限审核分开，且各自绑定记录内容及来源摘要；改动值、条件、适用范围或来源即使旧审核失效。候选、冲突、未知、明确不支持及已核验状态分开；新文件不能覆盖旧裁决。
4. 发布器只接受引用当前候选快照的记录，来源哈希及定位必须精确匹配；同一实体、字段、条件和适用范围出现相斥的已核验值时阻断发布。已核验记录必须有具名事实复审人和允许查看的角色；交付入口还需逐页核验与转发权限。未满足这些条件的记录留在候选侧，不进入可答集合。
5. 资料变更报告列出受影响的受治理记录。受影响记录须复审或降为不可答，才可生成新发布；不能让旧来源哈希在新发布里继续支撑确定答案。发布用不可变目录和原子活动指针；回滚只切换指针，不改旧快照。

## 更新频繁时的操作流程

`新归档 → 校验 → 候选抽取 → 来源差异/受影响记录 → 人工事实与权限复审 → 静态门 → Dev 回放 → 发布新快照`。新资料到达不改变当前已发布快照；有急迫错误时可生成将相关记录标记未知的修正快照，仍需复审、审计和独立回滚。相机知识和数采发布互不写入。

## 验收

合成资料覆盖重复导入、新增/修改/删除、双来源冲突、失效来源、未授权记录、失败发布保留旧指针与回滚。实际原包导入只生成候选清单和报告；真实参数、组合和链接须 K-2/K-3 负责人裁决后才进入可答快照。模型评测仅在 Dev，发布语义需独立复审。
