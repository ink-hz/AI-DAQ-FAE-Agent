## 实体身份与缺字段反馈修复

后续真实 Dev 题又暴露出两类独立缺陷：`EGO 双目` 是原始规格书支持的描述性家族称呼，却未作为受审别名发布；而旧工具把 `UMI Finger Pro`、`EGO Pro Max` 等未发布型号按已发布名称的子串归一，可能借到别的型号规格。新增别名作为实体记录的 `data.aliases`，随事实原件引用、事实审查指纹、角色权限指纹一起发布；运行时只把精确的已发布名称、规范 ID、产品键或别名当成规格工具的实体参数。`EGO 双目` 同时属于 1600×1200 和 1920×1200 两个变体，不指定选择器时只列候选条件，不能给一个无条件单值。

源文件逐页复核：两份 EGO 原始规格书的物理第 3 页均明确写有双目视觉、两颗摄像头，文件 SHA-256 分别等于已发布 `entity:ego-1600`、`entity:ego-1920` 的页级来源哈希。因此 `EGO 双目` 只能作两变体的描述性家族别名，不表示正式型号名、同一分辨率或鱼眼镜头。HUB 原文使用“数采 HUB”“集中式供电与同步触发中枢”，没有“集线器”，故不发布 `HUB 集线器` 为受审别名。

独立代码审查继续复现了小写未知型号后缀、中文“接口版”、别名抢占另一个产品键、别名抢占另一变体规范 ID，以及 `×`/`x` 归一化后碰撞的问题。现在离线记录门与运行时 manifest 门都检查规范 ID、名称、别名、产品键的归一化碰撞，允许同一家族共享产品键与同名变体；规格工具遇到多实体身份键直接拒绝。自由文本身份解析只接受受审标签、已审选择器与明确语法连接；Dev 候选预览沿用其原有宽松发现，不能把这种发现带到正式发布。相关测试覆盖未知型号、角色边界、选择器、碰撞和候选预览；隔离全量 Python 回归在最终代码上为 **987 passed**。
