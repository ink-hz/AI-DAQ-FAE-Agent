# 数采 FAE 首问 403 与企业会话恢复（2026-10-18）

## 现象与定位

用户在 `/daq/` 提问“你知道多少款数采产品”时，前端仅显示等待 Agent 事件，随后收到 `POST /chat` 的 403。线上同一时间窗口内有两次 `POST /enterprise/session` 成功、历史会话读取成功，而请求账本没有该问答的预留记录，因此拒绝发生在模型与知识工作流之前。后端身份边界在 Cookie 与 `X-DAQ-Enterprise-CSRF` 不一致时返回 `enterprise_csrf_invalid`；隔离的后端测试用旧令牌和新 Cookie 稳定复现 403。线上日志没有记录该 403 的响应错误码，故并发会话覆盖是由时间顺序和隔离复现支持的诊断，并非线上响应体的直接取证。

## 修复

- 内部 `/daq/` 完成 Platform 启动票据兑换后，立即读取当前 Cookie 对应的企业会话，再将账号与 CSRF 令牌交给 WebUI。
- 若后续聊天请求明确返回 `enterprise_csrf_invalid`，前端读取当前会话、更新账号与令牌，但不自动重发问题。不同账号可能有相同显示名，现有会话响应没有可安全比较的稳定主体标识；自动重发会把原账号的问题或附件送给新账号。
- 聊天被拒时清除旧会话与旧附件 ID，保留用户输入与本地文件供用户核对账号、重新上传并手动发送。延迟返回的历史会话详情不再恢复旧账号内容。非聊天写操作保留旧令牌，不能静默切换账号。
- 相机服务、共享 `src/`、DAQ 运行时、主知识与 SDK 发布指针均未修改。
