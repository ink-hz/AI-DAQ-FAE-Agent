## 0. 全局约束、文件地图与完成定义

- 相机 FAE 是**能力及质量门的工程基线**；相机产品事实不证明 DAQ 的产品事实。先核对相机的实际发布身份；不可读时写“仓库基线”，不称当前生产基线。
- 每条证据绑定代码、运行镜像、模型/网关、提示、知识/SDK、角色、入口与时间；缺失项显式记 `version_unknown`。旧结果仅说明旧版本。共享 `src` 树相同不等于 DAQ 工作流等价。
- 优先读现有 trace、发布清单、已审资料和源码，必要时做**无模型**探针。新真模型回放只在隔离 Dev，且只为一个尚不能区分的假设服务；生产 `/chat` 不发送评测题。
- 原问、附件、完整答案和内部 trace 如含敏感内容，放仓库中已被忽略的 `tmp/daq-camera-comparison-20261020/`；Git 中仅留脱敏摘要、哈希及受限指针。不得把候选文件或用户附件当作产品权威来源。
- `equivalent / confirmed_gap / excluded / evidence_blocked / not_applicable` 是能力对照状态；`historical_fixed / current_reproduced / never_implemented / version_unknown` 是时间属性。无证据时不靠设计文档、旧审计或回答长度补结论。
- 每项被审能力复制[记录模板](../specs/2026-10-20-daq-fae-comparison-record-template.md)到 `docs/reviews/2026-10-20-daq-camera-comparison/records/CAP-Lxx-nnn.md`。案例、证据、发现、改动、验证、发布使用稳定 `CASE/EVD/FIND/CHG/VER/REL` ID；本轮分析不虚构尚不存在的 `CHG/VER/REL`。

**落点**：`docs/reviews/2026-10-20-daq-camera-comparison/index.md`、`docs/reviews/2026-10-20-daq-camera-comparison/00-identity.md`。**覆盖层**：L01、L10、L11 的身份前提。

### A1：冻结症状锚点和同类任务样本

**落点**：`docs/reviews/2026-10-20-daq-camera-comparison/01-cases.md`、首批 `CASE` 记录。**覆盖层**：L11 的反馈输入。

- [ ] 从用户已给的实际问题和现存复审中先取 3–6 条纵向锚点，覆盖短答/漏答、有据弃答和多轮丢条件；记录原问、前文、角色、时间、可见完整答案、trace ID 或缺失原因、当时版本。2026-10-12、10-18、10-20 的旧结果按版本分栏，不混成当前生产失败。
- [ ] 冻结单事实、条件规格、复合目标、选型、SDK、排障、多轮七类任务的抽样框。每类分别标明 DAQ 是否有受审可答资料、相机对应任务的已审来源；不让相机回答 DAQ 产品题。
- [ ] 给每个案例写预期子目标和硬条件；短答不按字数判失败，而按用户需求及本轮已有证据的兑现判定。缺少真实生产短答案或 trace 时保留 `evidence_blocked`，继续使用已有样本做架构分析。

**验收**：样本选择先于新回放冻结，题目与预期变更会产生新版本；可以区分“实际用户症状”“历史 Dev 失败”“拟验证反例”。

### A2：建立相机成熟能力的可验证基线

**落点**：`docs/reviews/2026-10-20-daq-camera-comparison/02-camera-baseline.md`、相机侧 `CAP-Lxx-nnn` 记录。**覆盖层**：L01–L11 的基线列。

- [ ] 从相机工作流地图、实际发布源码、已存 trace/回归记录抽取上下文、请求 schema、实体接地、能力取证、知识分层、覆盖/终稿、outcome、反馈/评测等能力契约；逐项注明实际入口、输入输出及验证来源。
- [ ] 对每项契约标识“通用 FAE 能力”“相机域专用能力”或“尚缺运行证明”。例如不要求 DAQ 复制相机 `Orchestrator`，但须查 DAQ 怎样完成有效问句与切题；不把旧 Planner 当当前 Loop 路径。
- [ ] 对每层挑一条能证明能力生效的现存案例或合同，并记录版本。只有设计声明时标 `design_only`；实际生产身份与仓库版本不一致时分别列示。

**验收**：十一层都有明确相机锚点或说明为何该层不适用；每个“成熟能力”判断可追到代码及运行/回归证据，不靠文件名或口头印象。

### A3：沿代表性 DAQ 请求定位首次偏离

**落点**：`docs/reviews/2026-10-20-daq-camera-comparison/03-vertical-traces.md`、案例相关 `CAP` 记录。**覆盖层**：跨 L01–L10。

- [ ] 对 A1 首批案例依次记录入口/权限、原问与有效问、上下文、schema 子目标、工具参数与返回、知识范围、账本状态、`submit_answer`、后端/SSE/历史/UI；每个字段附同一 request/trace 和版本。
- [ ] 标出最早丢失目标、条件或受审事实的相邻两层，并与 A2 的相机能力契约对照；后续层只是放大或展示该问题时要分开记录。
- [ ] 为每种候选原因写一个能推翻它的同版本无模型探针或邻近正例。旧审计所说的 schema、泛检索和 trace 缺口逐项重新核对：现已修复、当前仍在或证据不足分别标记。

**验收**：首批三类症状各有一条完整证据链，或写清缺少哪段 trace/原问/发布身份；不能只凭最终答案推断最早失效层。

### A4：审计知识来源、发布、检索和可答范围

**落点**：`docs/reviews/2026-10-20-daq-camera-comparison/04-knowledge.md`、L05/L06 的 `CAP` 记录。**输入**：[原件覆盖审计](../../reviews/2026-10-16-daq-full-material-coverage.md)、实际知识 manifest、SDK/链接发布清单和 A1 任务分母。

- [ ] 以真实高频任务和七类题型为分母，按产品/变体、规格条件、组合拓扑、流程、软件兼容、SDK 用法、排障与官方链接建立矩阵；每个需求依次标“有权威原件、候选、已审发布、当前角色可见、工具检出、足以回答”。
- [ ] 抽查来源哈希、字段/单位/测量条件、版本与角色、冲突裁决；分别记录“来源本身缺”“来源有但未发布”“已发布但未检出”“检出却不支持该目标”。候选章节的相关性不当作 typed 规格证据。
- [ ] 对已发布正例和错实体、错变体、错版本、错测量条件、无权限负例做无模型工具探针，保存精确参数、命中 ID、状态与发布身份；可用现有工具测试入口，不调用回答模型。

**验收**：按任务可计算每一层损耗及明确分母；知识质量与工作流推理失败分开；L05/L06 有相机基线、DAQ 证据及判定。
