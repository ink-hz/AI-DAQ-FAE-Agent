# 数采知识内容复审队列（2026-10-10）

本轮将 B2 原件回查、字段候选、D2 增量复审项与 B3 章节审计汇入一份私有、**未签认**的内容队列，供苍渊按项裁决。构建器核对原记录与四组处置文件的 SHA-256、B2/B3 输入输出哈希链、原记录到章节的断言绑定、新记录的来源与适用范围，以及 B3 图中仅有的新增候选依赖。章节审计按图重新计算；哈希或绑定不符就拒绝出包。旧目录不覆盖，资料更新须用新目录重新构建。

| 私有文件 | 数量 | 审核内容 |
| --- | ---: | --- |
| `field-definitions.json` | 149 | 337 条字段候选按字段归并，含原件摘录、原始标签、单位、比较符、产品范围、B1 字典差异及章节；142 个新字段仍缺可信定义 |
| `content-decisions.json` | 48 | 冲突、复合、原文不符或无法安全解释的原候选，含原件回查记录、安全子候选及关联章节 |
| `section-reviews.json` | 114 | 章节全文、当前元数据、相关字段和裁决项，以及 293 条一致性发现 |
| `summary.json` | 1 | 上游文件和本轮输出哈希、数量及 `online_eligible=false` |

队列文件位于 Git 忽略的 `data/knowledge/curated/content-review-queue-20261010/v2/`，目录权限 `0700`，文件 `0600`；逐一回读输出哈希均匹配。`v1/` 是构建过程中的先前输出，`v2/` 补入了 B2 已回查的原件摘录，审核以 `v2/` 为准。记录上的 `review_sha256` 是内容版本指纹，**不是审核签名**。B2 原 572 项和新增 337 项 D2 包仍需逐项完成具名事实、权限及必要的页面审核；此队列也未给字段定义、正文或冲突任何审批。没有来源签认、原件独立归档及发布前审计，不得把队列导入为在线事实。

复现工具为 `python -m scripts.prepare_content_review_queue`，显式指定 `--b2-review-dir`、`--b3-review-dir`、`--originals`、四个 `--batch`、`--bound-section-index`、`--old-bindings` 和新 `--outdir`。审核顺序先处理 48 项内容裁决及字段定义，再依裁决重建正文/记录；任何修订生成新指纹并重新取得相应签认，之后才运行 D3。保留旧版本与来源影响图以支持高频增量更新。
