# DAQ / 相机 FAE 第一阶段对照结论

**调查范围**：2026-10-20 本机仓库与发布快照、相机带版本 Dev 回归、DAQ 六条历史隔离 Dev 失败及无模型工具探针。两服务**当前生产**构建/知识/模型身份和用户本次线上短答原题/trace 未取得；本页不宣称已经定位该次线上请求的根因。分析记录从[索引](index.md)进入，七项具体发现及反证见 [10-findings.md](10-findings.md)。

## 已经能回答的问题

1. **移植时通用运行时代码是否不同？** 两仓 `HEAD:src` tree 相同；不能把“共享 Loop 被复制坏了”作为当前仓库版本的解释。实际装配不同：相机当前 Loop 未注入可选领域证据 policy，DAQ 注入严格的需求账本 policy；DAQ 另加领域 schema、知识角色及发布链。质量损耗主要需沿这些差异和实际部署身份查。
2. **“回答短、答不出”是否全是知识不足？** 不是。旧 `CASE-001` 17 字来自 schema 错误；旧 `CASE-003/004` 已取得流程或四条 FOV 证据却没有正确认领/交付；旧 `CASE-005` 工具知道 SDK 版本而终稿说不知道。另一方面，当前发布快照的三设备同步、整机总供电、精确软件组合和官方链接确实无足够已审证据，应保留未知。这两类必须分别修。
3. **上下文是否整个丢了？** `CASE-005` 的同轮工具参数仍含 2.9.0，排除“整轮完全没带上文”。认证入口有带来源轮次的 checkpoint；旧案问题是结构化目标和终稿对已知字段的兑现不稳定。切题/纠正的当前生产效果尚未逐请求核对。
4. **模型/网关或页面是否导致这些旧案？** 四条保存完整事件的旧案有 Provider 模型回显、无重试/协议错误、预算未耗尽，SSE 与历史答案一致；这些旧案的首因不在网关截断或 SSE/历史丢字。当前线上 UI/模型身份仍未知。
5. **为何已有修复仍需警惕？** 最终代码的部分聚焦 Dev 复审通过，10-20 正式主知识和 SDK 五题复审也有证据；但最终代码+正式知识身份下核心 55 题未整套跑，13 组多轮只完成 9 组，不能把旧身份或局部通过折算为整套发布通过。
6. **Dev 与认证入口真的等价吗？** 10-20 源码不是：Dev 给 DAQ 证据策略传有效问句，认证聊天与 Task 没传。无模型对照中，一条无来源的 USB 连接说法在前者被要求改写、后者被放行（`FIND-007`）。这是已证装配差异，尚未证明它引发本次线上短答。

## 三个不同口径

| 口径 | 这次可复核结果 | 限制 |
| --- | --- | --- |
| 能力机制 | 11 层均建立 `CAP`，其中历史/发布快照 `confirmed_gap` 6 层、`evidence_blocked` 4 层、仅针对旧 SSE/历史假设 `excluded` 1 层 | 状态不是两侧全局得分；一个层中可有多个子机制。逐项见索引和记录 |
| 知识可答范围 | 本批 12 个原子需求，7 有角色可见的已审目标证据，5 无足够发布证据；27 条可答记录、0 章节只覆盖发布快照 | 不是 276 个原件的“完成率”，也不是 DAQ 全域准确率；当前线上知识指针未读 |
| 用户结果 | 六条旧 Dev 症状均有版本、答案哈希与 trace；其中 `CASE-003/004/005/006` 有端到端字段链 | 无当前用户线上原问/答案/trace；不能统计两侧当前答案质量差异 |

## 下一步按机制拆成五个独立工作包

| 包 | 输入与验收边界 | 优先 |
| --- | --- | --- |
| 生产只读定位 | 为 2–3 条用户实际短答/弃答收集脱敏原问、角色、trace、代码/模型/提示/知识回显、后端 done、SSE/历史/UI；按本索引找首次偏离。**不发送生产评测题** | P0，`FIND-006` |
| 目标与证据兑现 | 从 `CASE-001/003/004/005` 建原问→goal→条件→工具→匹配 ID→终稿正反哨兵；保留已知部分且不松错实体/错变体门；最终身份隔离 Dev 回放与独立 FAE/Codex 复审 | P1，`FIND-001/004` |
| 入口证据门一致性 | 把可信原问/有效问传给认证入口的 DAQ policy，按相同证据与答案比较 Dev/认证路径；先验证未明示连接、用户明示连接、请求 ID 与数值条件正反例，保留权限边界 | P1，`FIND-007` |
| DAQ 知识覆盖与发布 | 对三设备同步、总供电、精确软件支持、官方链接逐项核原件/owner/适用范围/角色；无权威原件则保持不可答，已审后发布新 ID 并做正反工具探针 | P1，`FIND-002` |
| 发布质量门 | 冻结 55 核心和 13 多轮，补六个失败族及相邻负例；结构错误和专业语义分门，记录未执行，代码/知识/提示/模型四身份一致；必要时跑相机旧域保护门 | P1，`FIND-003/005` |

完成这些工作包后，才可按 `FIND→CHG→VER→REL` 将某项修复标为已发布/观察；本轮只读调查不填写已修复生产状态。若无法取得线上 trace，最关键的当前生产归因保持 `evidence_blocked`，先推进有独立证据的知识裁决和质量门。
