# DAQ K-2 候选复审包设计

K-2 需要产品/研发负责人确认事实，也需要资料所有者/渠道负责人确认查看和转发范围。当前没有具名负责人。本批只准备可重跑的私有复审包，不生成 `verified` 记录，不发布或激活知识。

## 输入与输出

- 输入为 K-1 已验证归档生成的候选快照，以及 Git 内的稳定议题配方。命令重新导入归档并与快照逐项比较后才写输出。
- 配方按稳定议题 ID 列出复审问题、负责人类别和来源选择器。选择器以相对路径 glob 和正文正则寻找候选页/章节；命中只表示值得复审，不表示事实成立。
- 私有 JSON 包含归档身份、全部来源的路径及 SHA、每个议题的来源哈希、PDF 页码或文本行号、短摘录、来源自称密级、未命中选择器和待签认角色矩阵。输出仅能放在仓外或 Git 忽略目录，以 `0600` 创建。
- 资料上自称“公开”或“Confidential”只是候选标记。任何文件在资料所有者签认前都没有自动查看、转发或下载授权。

## 高频更新

每次拿到新原件，先建立新的不可变归档与候选快照，再由同一配方生成新复审包。`review-diff` 比较两包，列出新增/修改/删除来源、证据或定位变化的议题，以及没有被任何议题覆盖的变化来源。旧裁决不能自动继承到变化议题；无命中选择器进入人工查缺。配方变更也单独列出。K-1 的记录级来源哈希和审核指纹继续负责发布门。

## 人工签认出口

复审人根据原件及页/章节确认实体及别名、变体映射、条件化参数、组合拓扑与实际步骤，分别填写事实裁决和权限裁决。流程只覆盖原件支持的单机/组合、平台和连接方式；未完章节保留缺口。资料角色按 `internal_fae`、`tmall_support`、`channel` 分别确定查看和转发。确认后的内容再转换为 K-1 记录并通过 K-4 发布审计；本工具不替复审人作结论。
