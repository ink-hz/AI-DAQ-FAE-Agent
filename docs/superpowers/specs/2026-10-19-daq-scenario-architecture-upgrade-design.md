# 数采 FAE 扩展场景与证据范围架构设计

日期：2026-10-19。授权：用户要求参照相机 FAE 增加真实场景、先测试、查根因、升级 Agent 架构并再次测试。评测只使用隔离 Development；生产服务不承接评测流量。相机的工作流设计、四轴评测、30 道核心题、72 道泛化题、12 组多轮题和真实失败哨兵是题型与方法参照，产品事实只能来自数采当前受治理发布。

## 目标与判定

为当前主知识 17 条 claim、8 条实体、1 条单机拓扑、1 条单机流程，以及 SDK 23 条用法、17 条发布说明，建立跨目录、变体、测量条件、组合边界、SDK/固件版本、排障和多轮上下文的题集。新核心集至少 30 道单轮，另有至少 8 组三轮上下文题；保留 2026-10-18 的 L0、泛化与真实失败样本。题目记录预期证据和禁止的无据断言，结果按语义事实、运行硬门、协议一致性、展示质量四轴独立判断。自动硬门不能替代 Codex 或人工 FAE 读完整答案。

按冻结代码/知识身份先跑代表性发现批次，保留原始请求、答案、来源、trace 和结果哈希。根因必须落到工作流层：上下文、schema、规划、证据工具、覆盖、合成或终态。修复采用跨案例机制，不按问句词面做终稿扫描或重写。修复后以新代码 SHA 再跑所有失败哨兵、受影响核心题、L0、泛化及多轮，逐题独立复审；代码变更不能借旧发布身份宣称上线通过。

## 架构改动范围

1. **问题范围与目标。** 同一问题中单机、组合、模块、整机或不同变体是各自的证据目标。结构化输出须保留来源于用户原话的目标范围；对单机流程与多机同步的并列需求，分别取证，缺少组合证据不能抹去已审单机步骤。用于发布流程匹配的范围必须由用户原话和受审记录共同约束，不能仅凭模型写的工具查询放宽。
2. **供电问题。** 分开三个语义：下游口数量、每口输出、指定同时使用 N 口时的总输出。用户问“单口值能否直接当整机总量”是定性边界问题，必须回答前两项已审事实并指出总量缺证；不得把端口容量推成同时负载数量。非法聚合数值仍由 schema 拒绝或清除，不能成为可回答的事实。
3. **硬条件选型。** “原生”、稳定并发、整机精度等用户硬条件若没有同范围证据，在结构化需求账本中显式缺失。单项规格可比较，但最终推荐不得称其满足未证实硬条件；结论和建议保持同一限定。无需引入词表扫描、第二模型自评或固定答案模板。
4. **发布说明和 SDK。** 保留固件、Viewer、SDK 日志的产品、版本、构建作用域；日志只证明记载，不证明设备与软件组合实测。2026-10-18 的中文句界修复需在新代码身份下重放。
