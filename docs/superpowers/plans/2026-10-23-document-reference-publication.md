# 现有资料参考发布

用户授权：现有能力尽可能上线；有歧义可附条件交付，不等待全部候选章节成为确定参数。执行不再逐项请求确认。

## 设计

已核实规格继续优先。新增来源逐段核对的 `source_text` 记录，明确 `evidence_scope=document_statement_only`：仅确认资料写了什么，不代表设备测试、完整规格或组合验证。PDF 表格抽取保留页码与表格排列限制；不同版本并列，不裁决未核实冲突。仅 internal_fae 发布，原始路径不进入回答。

复用现有签名发布、章节、工具循环和 supporting evidence。`read_doc` 返回独立来源绑定的参考支持；它可以交付给用户，但不能满足规格、拓扑、软件兼容等硬事实目标。不得进入完整规格集合和产品计数。策略从角色可见的发布知识重新核对正文、记录和来源，拒绝伪造、错型号和未读引用。

## 执行顺序

1. 新增合成产品失败用例；实现参考投影、支持证据与提示约束。
2. 对原始 PDF/Markdown 按段落发布；核对已有 SDK 更新记录与索引文件处置。逐段内容与条件独立审核，不批量把候选物理事实改为已核实。
3. 仅新增受影响路径做隔离 Dev 真实问答和独立 Codex 答案复审。复用历史通过证据；失败才重跑。
4. 固定代码、主知识、SDK 和原件归档身份，独立签名、默认生产加载验证。
5. 备份当前生产组，只替换 DAQ；可回滚 image/env/main/SDK/source。相机及共享运行时不改。生产只读健康与身份检查，不做模型评测。

## 验收

有来源内容可以附限定交付；完整规格仍只含类型化事实；参考原文不能认证组合或显式变体；未读、篡改、错角色引用被拒绝。原件 hash、定位、清洗变换、独立审核、发布身份与回滚证据保存。实际部署结果单独记录，不把 Dev 通过写成线上修复。
