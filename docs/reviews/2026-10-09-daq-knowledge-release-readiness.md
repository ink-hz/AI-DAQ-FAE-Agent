首批真实资料已清洗成[66 条可追溯候选/冲突记录](../knowledge/2026-10-09-daq-k5-real-records.md)，但还不能称为完整知识库、达到相机 FAE 标准或已发布。真实来源及记录仍留在私有目录；代码推送和本机版本切换均不构成 Dev 服务或生产发布。

## 按依赖顺序完成

1. 将逐文件哈希的原始包放入可重取的受控持久存储，核验读取者和恢复测试；保留原件不可变。
2. 指定产品/研发、资料所有者和渠道负责人，签认首批产品实体、参数冲突、组合流程、角色查看/转发权限。未决项仍为 `conflict/unknown`。
3. 逐设备、修订、平台和连接方式核验软件/固件支持；逐页核验官方链接及交付权限；先裁决 EG-DB 的模块关系，再引入相机固定版本只读投影。
4. 将已清洗的候选/冲突记录逐条裁决并补具名事实与权限审核指纹，静态审计后发布新的不可变 DAQ 快照；接入检索前角色过滤，并在 Dev 演练切换、失败保持旧版和回滚。
5. 冻结真实 Dev 题集和预期，运行数采 Dev 模型回放，由独立 Codex 或 FAE 复审答案、来源、权限和缺证边界。共享运行时代码若有改变，先补相机 Dev 质量门。
6. Platform 身份与角色授权合同、入口、性能和独立部署回滚通过后，才决定内部试点；生产仅做只读发布核验。

高频更新按“新原件归档 → 差异议题 → 受影响事实和权限重审 → 新快照 → Dev 回放 → 切换/回滚”执行，旧快照不原地改写。可以缩小每批复审范围，不能继承已失效的来源哈希或扩大未签认的可见范围。
