### A. 来源处置与可读知识

**A1｜逐份来源处置和资产目录**（可立即执行；对应 K-1/K-2）。以现有受限归档和候选快照为输入，在 Git 忽略的 `data/knowledge/curated/` 形成 27 行文本处置表、249 行资产用途表及来源版本关系。每份文本标为 `curated / historical_duplicate / needs_ocr_or_parse / needs_fact_adjudication / out_of_first_scope`，写明理由、责任人、原件哈希、页/行与更新关系；资产只登记身份、类别、用途、授权待审状态，不将包内字节纳入默认文本索引。**验收：** 27+249 行与原始 manifest 一一对应，无遗漏/重复；同名异版可区分；人工抽查每类原件能复现定位；受限原文不提交 Git。

**A2｜产品知识章节**（依赖 A1；对应 K-2）。按设计的 `products/<entity_slug>/` 逻辑结构清洗 EGO 1600/1920、EGO Pro、EG-DB、WristCam、UMI Finger/视觉模块、HUB 的定位、规格、限制和软件入口候选章节。每节有稳定 `section_id`、实体 ID、适用变体/修订、精确来源、审核状态及角色草案；名称相似但未裁决的 SKU 留歧义，不自行合并。**验收：** 原文表值、单位、比较符和限定条件可逐节回对；产品 `index` 明示已有内容与缺口；任何候选数值、链接或受限段落不进入在线视图。

**A3｜组合流程与横切专题章节**（依赖 A1；对应 K-2/A-3）。单列 EGO 单机、EGO Pro 单机、EGO＋双 WristCam＋HUB，以及指南直接支持的 EGO USB/Wi-Fi PC 采集流程；另建同步/时间戳、落盘/格式、型号消歧、软件版本边界的候选专题。拓扑、供电、连接、Viewer/固件条件、步骤、检查点、失败分支和缺项分别标注。**验收：** 单机步骤不被复用成未验证多机流程；泛称 EGO 不自动选择 1600 或 1920 变体；每个流程步骤可回到原件页/行，未记载步骤保持缺口。

**A4｜选型、风险与排障候选章节**（依赖 A1/A2/A3；对应 K-2/A-3）。从已定位原件提取可证明的组合适用条件、限制、常见故障现象、检查顺序和数据完整性风险；把产品参数、组合实测、现场经验分别标明证据层级。原件没有覆盖的选型规则或故障步骤只登记缺口，不编写经验结论。**验收：** 每条推荐/排障步骤有准确适用产品、拓扑和来源；不能由单件参数推出整套方案可行；已审计缺口可供 `selection / troubleshoot / risk / experience` 工具明确返回。

### B. 身份事实、章节一致性与增量影响

**B1｜产品身份、字段和覆盖字典**（依赖 A1；对应 K-1/K-2）。基于现有 70 条记录形成正式名/别名/歧义名、产品与组件/套件关系、规格字段同义词/单位/比较符，以及按实体、字段、组合、来源、角色的覆盖表。覆盖状态区分已核验、仅候选、冲突和已审计无资料。**验收：** EGO Pro/Quad-EGO、EG-DB/RGB-D EGO、Wi-Fi 5/6、100/120 mm 等未决映射可见但不可自动裁决；无资料不写成 `unsupported`。

**B2｜结构化记录和章节同源一致性**（依赖 A2/A3/A4/B1；对应 K-1/K-2）。为章节建立 `section_id → claim_id/topology_id/procedure_id → source_ref` 依赖，复用 `daq_fae/knowledge/records.py` 的六类记录；已审核硬参数由记录生成或核对章节表格，章节与事实不得维护两套相斥值。新增章节审计和覆盖报告，保持 70 条旧候选及其稳定 ID。**验收：** 值、单位、条件、变体或来源任一不一致即失败；冲突保留各候选来源且不可答；精确变体或软件条件缺失时不能给确定结论。

**B3｜高频更新影响图**（依赖 B2；对应 K-1/K-4）。扩展现有 `compare_snapshots`/`impact_report`，建立来源→章节→记录→覆盖状态→Dev 题目的依赖图。新增、变更、删除、抽取器版本变化、角色扩大、SKU/字段定义变化分别产出重审清单；旧签认仅在来源、定位、条件和角色均未变化时复用。**验收：** 合成更新集证明只列出真正受影响项；删除来源撤回相关正向证据；新增资料触发相关 `unknown/unsupported` 复查；失败更新不改活动指针。

### C. 发布格式、检索和专门证据

**C1｜章节编译到独立知识版本**（依赖 A2/A3/A4/B2；对应 K-4）。扩展 `daq_fae/knowledge/releases.py` 与 `reviewed_view.py` 的发布格式，将审核后的章节、记录、来源/依赖索引、状态/角色摘要作为同一内容寻址版本；旧格式读取须有明确兼容或拒绝规则，不得静默误释。章节审核绑定内容、来源和角色，权限不同的段落拆节；发布前扫描正文 URL，交付链接只引用已审核链接 ID。**验收：** 候选章节不能编译为可读正文；改正文或来源使旧审核失效；非法角色/URL 阻止发布；重复构建同 ID、失败保持旧版。

**C2｜授权章节搜索与精读**（依赖 C1；对应 A-3）。在 `daq_fae/domain_tools.py` 增加 `read_doc(section_id)`，把现有 `search_knowledge` 从 JSON 子串匹配扩展为对授权章节的标题、别名、领域词和正文检索；继续保留类型化 `lookup_spec`/拓扑/流程查询。先用确定性词项与中文片语召回，结果附发布 ID、适用条件和结构化来源。**验收：** 自然语言问题能找到产品/流程/专题的正确章节；无权限节在搜索、精读和来源中均不可见；候选、冲突值与用户附件不会被当成已核验知识；模型正文不出现本地来源路径。

**C3｜软件、固件与 SDK 支持证据**（依赖 A1/B1；对应 K-3/A-3）。按 K-3 复审包补产品/修订、平台、连接、Viewer/SDK/固件版本、功能和证据等级关系；包存在、文档声明、源码支持、单设备实测和端到端组合实测分开。**验收：** `check_software_support`/`sdk_evidence` 只在条件精确匹配且记录已审核时返回支持；缺版本或缺实测给相应缺口，不从压缩包名推断兼容。

**C4｜官方链接与交付权限**（依赖 A1；对应 K-3/A-3）。逐页核验拟交付的产品页、文档和下载页，记录最终 URL、页面内容/版本、准确 SKU 映射、复核日期及各角色查看/转发裁决；与 `link` 记录和 `official_links` 工具接通。**验收：** 每个可返回 URL 有独立浏览核验与 `link_review`，本轮工具真实返回且当前角色有交付权；本地路径、包名、原包 HTML/README 中的 URL 不能直接输出。

**C5｜Gemini 335L 模块边界**（依赖 B1；对应 K-3）。先由苍渊裁决 EG-DB 所含模块的准确型号/修订，再取得相机仓固定版本的只读模块事实投影；记录投影来源和再发布审计。**验收：** 关系未确认时不引用模块事实；模块标称参数仅表述为模块信息，不能作为 EG-DB 整机精度、同步或 SDK 能力。

**C6｜认证角色与冲突可见性合同**（与 C1/C2 联调；对应 A-1/K-4）。在 `daq_fae/app.py` 的非空知识认证门前接可信的 Agent 身份及 `internal_fae / tmall_support / channel` entitlement 映射；映射缺失或跨 Agent 身份直接拒绝。冲突只在其状态与可陈述范围经过单独权限审核后提示，否则返回不泄露候选值的缺证状态。**验收：** 检索、精读、事实、链接及 trace 均按同一授权视图过滤；仅有企业成员身份不授予资料权限；角色撤销、扩大及跨 Agent token 用例通过。

### D. 真实审核、Dev 知识发布与质量门

**D1｜受控持久原件与恢复验证**（可立即推进，D3 硬依赖；对应 M0-4/K-4）。将现有逐文件哈希原包复制到有访问控制的仓外持久存储，登记保管位置、读取权限、只读策略与版本，另机或独立位置重新读取并对 276 份文件做哈希/大小核验；保留同机原件直到恢复验证通过。**验收：** 有可复查的权限和重取记录，原包与清单完全相同；`tmp/` 保持 Git 忽略且不作为发布输入。

**D2｜苍渊逐条事实和权限裁决**（47 条可立即复审；最终依赖 A/B/C3～C5 的相应内容；对应 K-2/K-3/K-4）。用 K-7 私有提案及原件页/行，分别签认事实、适用条件和查看/转发角色；需改值或范围时生成新指纹后重审。23 条暂缓项逐条记作继续冲突、待补来源或已裁决；流程、软件、链接及章节也各自留下具名审核，链接另有逐页核验。**验收：** 每个进入可答范围的项目有事实审核与独立权限审核摘要，来源和记录指纹匹配；“苍渊负责”或预填指纹不算通过；未决内容不被批量改为 `verified`。

**D3｜静态审计、真实 Dev 发布与回滚**（依赖 B3、C1～C6、D1、D2；对应 K-4/V-1）。冻结首期可答问题范围及明确缺口，校验来源、章节、记录、角色、链接、覆盖和运行时兼容版本后，构建不可变 Dev release；显式激活，验证失败保持旧版与回滚。若某专题仍未核验，发布清单明确排除该专题及其可答承诺。**验收：** release 清单有归档哈希、各层数量/状态/角色、审核摘要、评测批次和前版 ID；Dev 健康/trace 报告同一 release ID；相机发布指针、配置和索引无变化。该步不是试点或生产部署。

**D4｜真实 Dev 问答及独立复审**（依赖 D3；对应 V-1/V-2）。回放冻结的产品身份、规格冲突、组合流程、软件/链接、权限、多轮、缺证、Provider HTTP 400/503 与更新回滚题族，逐题保存问答、来源、计划/实际能力、覆盖、fallback、outcome、trace ID、耗时、版本和复审结论；由独立 Codex 或具名 FAE 判断语义质量。**验收：** 零严重型号混答、权限泄漏、无据 `resolved`、运行错误伪装知识缺口；失败定位到来源、治理、检索、覆盖或合成层并保留原记录。模型回放只在 Dev；如改共享运行时，另过相机 FAE 旧域质量门。

## 3. 执行证据与状态规则

每项任务结束交付准确提交/知识版本、输入清单哈希、结果文件或测试输出、未通过项、审核人及下一步依赖。工程实现项各自先写合成失败用例再实现；内容清洗项抽查原件定位和边界；发布项保留切换前后指针及回滚记录。真实资料、审核表和原文放在 Git 忽略的受限位置，仓库只提交合同、工具、测试和脱敏审计摘要。

状态只用 **未开始 / 候选已备 / 工程已实现待真实验收 / 已验收** 四档。本任务书建立时，A1～D4 均不能标为“已验收”；K-1 导入/发布工具与 K-4 合成消费者属于现有底座，不重复算作真实知识完成。按 A1、A2/A3/A4、B1/B2 先启动；D1 与 K-7 的 D2 复审同步推进。P/V 试点门另见总任务书，知识库专项验收不自动打开试点。
